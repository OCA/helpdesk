This module lets you replace the free-text *Description* field of the
Helpdesk portal ticket form with a structured, admin-defined set of
questions, chosen automatically from the selected category.

Instead of giving customers an empty text box, you stay in control of
the questions asked. When a portal category has a form attached, its
questions are loaded inline (no page reload, no survey redirect) as soon
as the customer picks the category. The submitted answers are rendered
as HTML into the ticket description, so agents read a clean, consistent
report and notification emails work unchanged.

Categories without a form fall back to the standard free-text
description, so the module is safe to install on an existing setup.

Configuration
=============

The portal form only appears when categories are selectable in the
portal.

1. Go to *Helpdesk > Configuration > Settings* and enable **Select
   category in Helpdesk portal**.
2. Go to *Helpdesk > Configuration > Portal Forms* and create a form,
   give it a name, an optional introduction, and add questions. Each
   question has a type (single line text, multi line text, single
   choice, multiple choice, or yes/no) and can be marked as required.
   Single and multiple choice questions hold their own list of choices.
   This module also includes support for conditional questions.

|Category portal form configuration|

3. Go to *Helpdesk > Configuration > Categories*, open a portal-visible
   category and set its **Portal Form**.

Categories left without a portal form keep the standard free-text
description.

Usage
=====

On the portal, a customer opening *Submit a Ticket* selects a category
as usual. If that category has a portal form, its questions appear
immediately below the category, replacing the free-text description.
Subject and attachments behave as before.

|Portal ticket form|

On submit, the answers are formatted and stored as the ticket
description, where agents and notification emails read them like any
other description.
